# OpenPINN 双说明书

编写基准：2026-10-11；2026-10-12 同步解析圆孔；2026-10-14 将开发者说明书重构为贡献者指南；2026-10-16 修正首次安装、先构建后打开网页及按实际下载文件名运行的流程。包版本为 0.2.0。

## 阅读

- `public/user_manual.html`：20 个正文章节和完整方法选项附录，只说明具体使用。
- `public/developer_manual.html`：贡献任务路线、开发契约与源码索引，面向继续建设软件的开发者。

两份 HTML 均内嵌 CSS/JavaScript，可离线单独阅读；一起复制可保留相互切换链接。无需 CDN。打印按钮会先展开附录，开发者版较长，请按需选择打印页。

上述 `public/` 内的独立说明书已随源码提供。下面的 Sphinx 网站入口则必须先在项目根目录完成依赖安装并运行 `python scripts/build_docs.py` 才会生成；刚下载源码时没有 `docs/_build/html/` 是正常情况。Windows 未激活环境时使用 `.\.venv\Scripts\python.exe scripts/build_docs.py`。

构建后的 Sphinx 文档首页和左侧目录仍提供两份站内说明书入口；使用者入口位于
「用户指南」组，开发者入口位于「开发者」组：

- `docs/_build/html/user_guide.html`：站内使用者说明书。
- `docs/_build/html/developer_guide.html`：站内开发者说明书。

站内两份说明书各有 6 个真正的子页面，总览页只展示分类和阅读路线；左侧目录提供二级页面入口，不再把几十章全部堆在单页。
`docs/_ext/manual_sections.py` 是分类映射的唯一来源；新增正文节时必须分配到一个且仅一个子页面，否则构建报错。
`docs/_ext/openpinn_manuals.py` 从独立 HTML 按映射提取正文嵌入各 Sphinx 子页面，并把跨页锚点改写为文件链接。
`docs/_static/manuals.css` 与 `manuals.js` 提供站内样式和交互，无需维护两套正文。
更新正文后须按下列顺序先生成手册，再构建网站。

自定义建模是两份手册的重点：使用者第 06 章提供三个跟做案例及生成代码核对表；
开发者第 1 章提供环境准备和首次基线验证；第 16 章提供关键函数契约、参数映射和联动验收矩阵；第 19.4 节通过解析圆孔的实际案例讲解修改与测试；第 21/23 章提供协作验收、交接记录和统一构建。
案例操作说明不等于正式收敛测试结论。

## 维护

### 可点击流程图与思维导图

两份总览开头使用 SVG 总流程图，不再把章节目录卡片当作框架图。
使用者图包含内置 / 自定义分支、几何 → PDE → 边界、生成脚本、运行、验证与返回修改；
开发者图已改为反馈/提案 → 基线 → 算法、数学问题或维护任务 → 实现 → 测试 → PR → 审阅与维护；测试失败和审阅修改均有返回分支。原运行架构在“架构与源码参考”中按需查阅。
六个章节入口折叠在图后方，左侧目录保留。完整独立 HTML 开头也包含相同流程图。
使用者正文保留 4 张图，开发者正文保留 4 张图，共 10 张不同用途的图（含 2 张总览图）。
使用者仅覆盖自定义建模主流程、几何入口选择、边界选择和结果文件分流；
开发者仅覆盖模块职责、方法到组件、预览与生成代码的分支关系、验收层次。
不是每章都放图。筛选标准和两类读者的走查调整见 `diagram_review.md`。

总框架图定义在 `docs/_ext/manual_frameworks.py`；正文辅助图定义在 `docs/_ext/manual_diagrams.py`，共享样式在 `docs/_static/manual_diagrams.css`。
`build_manuals.py` 在分页前注入图形；站内链接由分页扩展改写，独立版保留本地锚点。
所有框架图方框与正文图节点都是原生链接，支持 Tab / Enter、离线和禁用 JavaScript；不依赖图片服务或 CDN。总图在窄屏保留最小字号并允许横向滚动。
流程箭头表示操作 / 处理次序；树形连线仅表示分类或条件分支，不能理解成逐函数调用。
已有参数表、接口契约表和测试矩阵保留；总览目录列表由图替换，部分开发调用文本折叠保留。
新增节点必须有有效目标。`tests/js/manual_diagrams.test.cjs` 检查所有目标、页面覆盖及独立版一致性；
它不代替真实浏览器窄屏、缩放、打印和键盘视觉检查。

人工正文位于 `_sources/`，不要手工编辑 public 中的构建产物。

开发者的新增贡献路线正文在 `_sources/developer_contributing.html`，技术正文仍在 `developer_content.html`。
独立开发者版按 `MANUAL_PAGES` 同网站一样排序：开始贡献、算法、数学扩展、维护、交付、架构参考。
此次未修改使用者正文、页面分组和总流程图。角色走查与具体修订见 `contributor_review.md`。

首次开发准备：安装 Python 的 `.[test,docs]` 可编辑依赖，并使用可用的 Node/npm 执行 `npm ci --ignore-scripts --no-audit --no-fund`。项目锁定 jsdom 开发测试依赖；不需要个人临时目录中的 NODE_PATH。具体跨平台命令和环境检查见开发者第 1 章。

在项目根目录执行统一交付入口：

```bash
python scripts/build_docs.py
```

入口按顺序生成双说明书、验证示例、强制构建 Sphinx，最后更新同日期 ZIP。任一步失败即停止；旧产物可能保留，不能当作本次成功交付。Shell/PowerShell 的 build_docs 包装和 check 脚本的文档阶段均调用此入口。直接执行 Sphinx 不会自动更新说明书源；分步命令只用于排错。

目录交互回归：先构建再执行 `node tests/js/manual_navigation.test.cjs`；全部 JS 测试使用 `npm test`。
覆盖两份总览、12 个站内子页面与两份独立版的分类、跨页链接、内容覆盖、旧锚点映射、小节高亮、历史和检索；
DOM 测试不能代替真实浏览器的视觉验收。

独立 HTML 保持完整内容用于离线归档和打印，其目录也改为 6 个折叠分类。日常阅读推荐站内分页版。
总览、子页面及独立版的普通文字链接不使用历史访问紫色，只有按下（CSS :active）时短暂为紫色；松开后恢复蓝色，键盘焦点用轮廓提示。左侧当前页面和页内当前小节仍保留结构性高亮，翻页按钮保留主题样式。`tests/js/manual_link_colors.test.cjs` 以等特异性的类模拟伪状态检查层叠规则，不读取浏览器隐私访问历史，也不等同于视觉验收。
页面旧链接（如 `developer_guide.html#registries`）在启用 JavaScript 时转到对应新子页面。子页保留原节编号和锚点以兼容正文中的引用；当前页面由 Sphinx 导航显示，本页小节高亮不使用 visited 历史色。

`manual_build_report.json` 记录索引规模；`manual_validation.json` 记录本次结构与示例验证结果。源码变更后需重新生成，并人工核对正文。AST 索引不是完整运行时调用图；JavaScript 附录只索引命名函数声明。

## 验证范围与记录

验证脚本执行标记的短示例：基线、方法组合、双隧道、自定义问题、完整 Trainer 恢复，以及新增解析圆孔法向/Robin 契约检查。当前结果以生成的 `public/manual_validation.json` 为准，不把固定通过数量当作所有后续版本的结论。

`tests/unit/test_documentation_build.py` 检查流水线顺序、压缩包内容及失败停止。交付还需独立执行 `npm test`、`python -m pytest -q -ra`，记录跳过原因；构建入口不自动执行完整测试套件。DOM 检查也不代表已经做了真实浏览器视觉/拖拽验收。

最初说明书任务未修改训练算法；2026-10-12 几何更新另增解析圆孔代码生成、可选分层边界采样、孔洞法向及相关回归，详见开发者第 07/17 章。
本次没有重新进行正式收敛比较、真实浏览器视觉排版或缩放拖拽验收；短训练不构成精度结论。
