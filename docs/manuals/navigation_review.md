# 双说明书分页后的双角色检查

日期：2026-10-12。范围：信息组织、阅读路线、生成页面内容与 DOM 行为。
这是按使用者/开发者任务进行的内部走查，不是实际用户访谈，也不代替真实浏览器视觉验收。

## 使用者角色

任务：第一次运行 → 自定义区域（图片/DXF）→ PDE 与边界 → 保存代码 → 训练 → 结果评价。

- 原问题：几十章集中于一个长页面，点击“目录”仅在同一页面滚动。
  修正：总览仅保留 6 个独立子页面入口，左侧为两级目录；小节导航在各页内默认折叠。
- 走查发现：几何单独成页后，用户可能不知道去哪设置 PDE/边界。
  修正：建模页与几何页双向引导，建模页直接提供训练与结果入口。
- 走查发现：搜索框可能被误认为全站搜索。
  修正：明确标为“筛选本页小节”，提示不隐藏正文；全站导航仍使用 Sphinx 的搜索入口。
- 完整性：所有原正文节和方法参数表都分配到唯一子页，未删除内容。

## 开发者角色

任务：接手环境 → 找到代码职责 → 修改网页/后端 → 测试 → 交付。

- 原问题：入门流程、内部实现和大规模函数索引处于同一页。
  修正：拆为接手、数学接口、训练执行、网页配置器、协作交付、函数参考 6 页；函数索引不再出现在入门页。
- 走查发现：“两套注册机制”不直接表达用途。
  修正：改为“方法配置与计算组件：从选择方法到创建对象”，保留代码类名。
- 走查发现：新增方法的接入清单与训练机制分开后可能难找。
  修正：训练执行页直接链接到接入清单和交付页；配置器页直接链接到后端契约、环境与函数参考。
- 走查发现：拆页会使旧章节锚点及跨章节引用失效。
  修正：共享映射重写跨页链接；旧总览链接的锚点在启用 JS 时路由到对应页面；原节编号与锚点保留。

## 自动检查依据

- `tests/js/manual_pages.test.cjs`：总览每套 6 个真实页面、正文无遗漏/重复、内部链接和旧锚点映射、两种任务阅读路线、侧栏当前页面。
- `tests/js/manual_navigation.test.cjs`：12 个子页面和两份单文件版的小节切换、深链接、历史导航、检索与颜色规则。
- `manual_sections.py`：新增节未分组、分组重复、锚点重复时拒绝构建，防止后续内容静默丢失。
- `python scripts/build_docs.py`：示例验证、Sphinx 强制重建、站内/独立版和下载包同步。

离线单文件版仍保留完整正文以便打印/归档，但导航改为 6 组折叠项；网站分页版是日常阅读入口。
本次不声称完成真实浏览器窄屏、缩放、屏幕阅读器和 Windows 实机验收。
